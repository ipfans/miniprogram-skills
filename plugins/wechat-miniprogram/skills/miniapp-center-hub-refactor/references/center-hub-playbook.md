# Hub 重构操作手册

审计清单、分区设计规则和迁移指引。

## 问题信号

当以下信号同时出现多个时，考虑 hub 重构：

- 用户需要记住多个不相关的 Tab 才能完成一个工作流
- 原来的"个人中心"或"我的"页面已变成导航垃圾场
- 待办和设置都很重要，但都没有明确归属
- 集成、提醒、个人状态同时竞争顶层位置
- 同一目标页从多个 Tab 链入，因为归属不清

## 审计表

改动路由前先建立审计表：

| 当前入口 | 用户意图 | 使用频率 | 是否需要详情页 | hub 内归属分区 |
|----------|----------|----------|----------------|----------------|
| _(逐行填写)_ | | 高/低 | 是/否 | |

常用归属分区：

- 待办 / 审核工作
- 集成 / 数据源
- 提醒 / 通知
- 个人设置 / 偏好
- 服务状态 / 环境信息

## 分区设计规则

hub 快速回答两个问题：
1. 现在需要关注什么
2. 在哪里管理支撑性设置

推荐结构：

- hub 作为一个顶层 Tab
- 内部设置显式归属的分区或 Tab
- 摘要行留在 hub 上
- 详情页保留在摘要行背后

适合作为 hub 摘要的信息：

| 摘要类型 | 示例 |
|----------|------|
| 待办计数 | 3 条待审核 |
| 未读计数 | 5 条未读消息 |
| 连接状态 | 已连接 / 已断开 |
| 提醒状态 | 2 个即将到期 |
| 同步模式 | 自动同步 / 已暂停 |

## 迁移清单

1. 冻结新的顶层 Tab 列表
2. 确定 hub 名称和内部分区
3. 将每个旧顶层目标映射到：
   - 保留顶层
   - 移入 hub 摘要
   - 保留为详情子页面
4. 更新深链接和按钮跳转目标
5. 旧详情页保留到新 hub 导航验证通过后再移除
6. 同步更新路由文档、冒烟检查和截图

## 反模式

| 反模式 | 说明 |
|--------|------|
| 一页收纳所有 | 用一个巨大的无分隔页面替代多个 Tab |
| 频率混排 | 高频操作和低频设置混在同一滚动区块，无分区边界 |
| 盲目删除详情页 | hub 存在后就删除详情页，即使流程仍需独立状态 |
| 按组件复用移动 | 按代码复用而非用户归属分配页面位置 |
| 用 hub 掩盖问题 | 需要更清晰状态或文案的问题，用导航重组来回避 |
