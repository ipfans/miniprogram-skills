# Prompt 示例

可复用的触发示例和评估说明。

## 触发示例

### 整体重组

```
我的小程序有 5 个底部 Tab（首页、消息、发现、我的、设置），用户反馈找不到待办和集成管理。帮我重新规划导航结构。
```

预期行为：审计全部顶层 Tab 和详情页，按归属权设计 hub 分区，输出迁移映射和执行顺序。

### 个人中心膨胀

```
"我的"页面现在包含订单、收藏、设置、消息、积分、优惠券，太长了。帮我拆分。
```

预期行为：识别高频操作（订单、消息）和低频设置（积分规则、优惠券管理），提议 hub 内部分区，将需要独立流程的页面保留为详情子页面。

### 待办入口不清

```
用户不知道该去"消息"还是"我的"处理审核任务，两边都有入口。
```

预期行为：识别归属不清的重复入口，将审核任务统一到 hub 的"待办"分区，保留详情页。

### 集成管理散落

```
第三方集成配置分散在设置页、首页快捷方式和个人中心三个地方，帮我统一。
```

预期行为：建立审计表，将集成相关入口统一归属到 hub 的"集成"分区，更新跳转路径。

## 非触发示例

### 仅修改文案

```
"我的"页面的标题太长了，帮我缩短。
```

此请求属于文案优化，不涉及导航结构重组。

### 仅调整样式

```
底部 Tab 的图标颜色不统一，帮我调整。
```

此请求属于视觉样式调整，不涉及信息架构。

## 评估要点

| 维度 | 良好 | 不足 |
|------|------|------|
| 审计完整性 | 所有顶层入口和详情页均出现在审计表中 | 遗漏了隐藏入口或深链接 |
| 归属清晰性 | 每个页面有且仅有一个归属分区 | 同一页面出现在多个分区 |
| 频率分离 | 高频操作和低频设置有明确分区边界 | 混排在同一滚动区块 |
| 迁移安全性 | 旧入口均可通过新路径到达 | 删除旧页面后部分流程断裂 |
| 可操作性 | 输出包含具体的迁移顺序和第一步操作 | 仅描述理想状态 |
