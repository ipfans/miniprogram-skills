# 验证 Prompt 示例

可复用的触发示例和评估说明。

## 触发示例

### 验证已有项目

```
检查这个小程序项目的结构是否符合官方规范。
```

预期行为：从 `project.config.json` 开始，逐项检查 app 入口文件、pages 路径、组件文件集、TypeScript 配置，输出四段式报告。

### 新建项目骨架

```
帮我搭建一个小程序项目的初始结构，使用 TypeScript。
```

预期行为：生成包含 `project.config.json`（含 `useCompilerPlugins`）、`tsconfig.json`、`app.ts`、`app.json`、`app.wxss` 和一个示例页面的完整文件集。

### 混合仓库验证

```
我的仓库里有 docs/、server/ 和 miniprogram/ 目录，检查小程序部分的结构。
```

预期行为：识别出仓库使用 `miniprogramRoot`，验证 `project.config.json` 的指向，然后在代码根目录内逐项检查。

### 单项检查

```
检查 app.json 的 pages 配置是否和实际目录匹配。
```

预期行为：读取 `app.json` 的 `pages` 数组，逐一验证每个路径下是否存在完整的页面文件集，报告多余或缺失的路径。

## 评估要点

| 维度 | 良好 | 不足 |
|------|------|------|
| 完整性 | 所有检查项均有覆盖 | 跳过了 TypeScript 配置或组件检查 |
| 准确性 | 报告基于实际文件系统 | 凭猜测判断文件存在 |
| 兼容性 | 正确识别 JS/TS 项目类型 | 假设所有项目都是 JS |
| 可操作性 | 给出具体的第一步修改 | 仅列出问题没有建议 |
| 简洁性 | 四段式结构化输出 | 冗长的叙述性文字 |
